# Research review and gap analysis (2026-10-17)

Scope: (1) re-check every paper cited in `docs/RESEARCH.md` sections B and G, (2) add newer papers (2023-2026) on the parts of the product the first round did not cover, (3) compare what the literature says with what is actually built, (4) propose five simple improvements.

Access note: the org asks that scholarly access go through the LibKey connector; it is not authorized in this session, so everything below was checked against public arXiv, ACL Anthology, ICLR and publisher pages.

"Verified" means I opened the page and the title, first author and the quoted finding match. "Venue not on page" means the arXiv page does not state the venue; I give it from memory and mark it. Nothing is invented; unconfirmed items are labelled **unverified**.

## 1. Summary

- **What we built, honestly:** context gating, a hand-seeded graph (77 nodes, 142 links, one hero scenario), hybrid manual search, a Qwen claim writer, MiniCheck plus a misattribution rule, a sufficiency gate, source cards with veteran attribution. Not built: the watcher (`backend/watcher/` is empty, no `/alerts` handler), capture/referral/feedback endpoints (only `/health /session /chat /sources` exist per README), the command catalog in the answer path (`lookup()` returns `commands`, `answer()` drops them), any staleness handling.
- **Citations:** 5 of the cited items need a text fix (B2, B4, G2, G6, G10) and several more need a caveat (details in section 2). Most serious: the "KG + LLM diagnostics" paper (2505.21291) is a **nuclear-plant** paper, not battery/aviation/FMEA; the Sufficient Context paper says the **opposite** of "fine-tuning helped modestly" (fine-tuning to say "I don't know" did not increase abstention); the Ciena "+16.5 pts over baseline RAG (88.5%)" wording is ambiguous or wrong.
- **Literature mostly supports the design.** Context locking (VersionRAG, Ciena), deterministic graph queries (arXiv 2605.26874), a sufficiency signal (Joren et al.), citation requirements (ALCE), explicit conflict handling (RAMDocs, CONFLICTS).
- **Literature points at four weak spots:** (a) a claim verifier can pass negation-inverted claims, and a published stress test now shows MiniCheck is one of the metrics that struggles with logically equivalent negations (this matches what we observed); (b) veteran notes are reachable only through the entity graph, so tacit knowledge not linked to a known alias is invisible; (c) stale or older-edition documents actively override correct answers, and our 2005-2014 manuals are used on an L-series node; (d) our evaluation sets are too small and too self-written to support the percentages we quote.
- **Core value check (junior operator + undocumented veteran knowledge + warnings + fixes + incidents):** knowledge capture model, attribution and context safety are good. Warnings are the biggest hole (design only). Veteran knowledge retrieval depends on hand-built graph links.

## 5. Five simple improvements (priority order)

All are small and stay inside the "do not overengineer" rule: no new services, no new models, no fine-tuning.

1. **Show veteran claims verbatim; add a polarity check.**
   What: for the veteran lane, render the note's own `call`, `why` and `not_when` fields (already structured in `heuristic`) instead of an LLM paraphrase; the LLM only chooses which notes to show. For remaining LLM claims add a cheap regex check that "not / do not / never / don't" in the source text is mirrored in the claim.
   Impact: removes the failure class we observed (0.97 on an inverted note), cuts MiniCheck calls and latency, and makes attribution exact.
   Papers: N9 (MiniCheck and negation), N11 (citation support is often incomplete), N10 (citation and refusal behaviour), N12.

2. **Add a fallback search over approved veteran notes, inside the context filter.**
   What: a `heuristic` vector (or hybrid) search over `trigger_text` using the embeddings that are already stored, filtered by `context_where('h')` and `status='approved'`, merged into `answer()` next to the graph walk. If nothing resolves to a graph entity but a note matches, show it with a lower-confidence label instead of an immediate refer.
   Impact: closes the biggest hole in "uses undocumented knowledge": notes no longer depend on hand-written aliases and edges. Safe because the node/series filter is unchanged.
   Papers: N5 (OM-RAG, flat retrieval over symptom-cause-resolution notes), N4 (structure helps but modestly), N2 (retrieval conditioned on applicability).

3. **Build the minimal watcher and measure lead time.**
   What: about 60-100 lines of plain Python that reads a replay file of events and metrics (3 scripted scenarios), matches the `pattern` JSON of approved `is_trigger` notes in a sliding window, writes `alert` rows, and lets the LLM write only the explanation text with the note's citation. Report "warned N minutes before failure in K of K replays" and false alarms on a normal replay.
   Impact: converts the weakest of the three core promises into a demonstrable one and gives the number the design already calls the proof.
   Papers: N14 (rules are transparent but need tuning), G4 RCACopilot (deterministic collection first), N3 (expert annotations to cut false alarms). Note the literature gives no lead-time benchmark; ours is the evidence.

4. **Tell the model and the reader what is old and what disagrees.**
   What: (a) put the edition and year in each MANUAL source header handed to Qwen and add one deterministic banner when the node is L-series and the cited manual is J/H ("older edition; verify on this node"); (b) for any `contradicts` / `disagrees_with` edge, render a fixed side-by-side card "Manual (edition) says ... / Veteran X says ... (scope, not-when)" from the stored text, and let the LLM write nothing for that part; (c) flag notes whose `last_validated` is older than a set threshold and use the `feedback` "outdated" action to demote them.
   Impact: addresses stale-edition risk and makes conflicts readable without trusting a 4B model to narrate them.
   Papers: N8 (stale-document poisoning), N6 and N7 (conflict handling), G1 and G2 (version metadata).

5. **Make evaluation independent and report intervals.**
   What: have a teammate who did not build the pipeline (ideally a veteran for the veteran items) write about 60 items, at least 10 each of: veteran-note questions, node-swapped traps, polarity-inverted veteran claims, near-miss sufficiency cases (right subsystem, wrong command), and manual-vs-veteran conflicts. Report each rate with a Wilson interval and the item count; keep the 27-question set only as a smoke test. Also record false-refusal rate next to correct-refusal rate.
   Impact: stops us quoting 81% or 10/10 as if they were stable, and finds whether improvements 1-4 actually help.
   Papers: N15 (error bars), N7 (expert-annotated conflict benchmark), N9 (perturbation tests), N11 (citation recall and precision), N13 (abstention metrics), N10.

Not recommended now: fine-tuning for abstention (B2 shows it did not work for a 7B), multi-agent conflict debate (N6, too heavy for a 4B model), bi-temporal ledger systems (preprint 2606.26511 appeared in search, not opened), GraphRAG (already skipped in RESEARCH.md for good reason).
